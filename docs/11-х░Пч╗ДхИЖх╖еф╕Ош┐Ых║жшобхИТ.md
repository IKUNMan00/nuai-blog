# 《我的知识小栈》小组分工与进度计划

> 适用：4–5 人课程小组。角色不固定，全员参与前后端、数据库全流程；以下为“主责 + 协作 + 评审”安排，可按实际人数裁剪。

---

## 1. 分工原则

1. **一人一个主模块**：每个人至少对一个模块的代码、测试、文档负责；
2. **主责不等于包办**：主责人设计方案，其他人参与评审、联调、补测试；
3. **前后端交叉**：后端同学至少改过一个模板，前端同学至少写过一个接口联调；
4. **数据库全员参与**：一起评审 ER 图与字段，避免“只有一个人懂表”；
5. **文档跟着代码走**：功能合并时同步 README / 接口 / 数据库文档；
6. **可追溯**：每项工作对应 Issue、分支、PR、提交记录。

## 4. 每周站会模板

```text
姓名：
上周完成：
  - 
本周计划：
  - 
当前阻塞：
  - 
需要谁协助：
  - 
```

会议规则：

- 每人 3 分钟，不展开技术细节；
- 阻塞问题会后单独拉人；
- 会议结论写进 Issue/群公告；
- 不超过 30 分钟。

## 5. 任务拆分与 Issue 规范

### 5.1 一个合格的任务

- 有明确验收标准（可勾选）；
- 预计 0.5–2 天完成；
- 只涉及 1–2 个模块；
- 有负责人和截止日期；
- 关联分支 / PR。

### 5.2 示例

```text
[Feature] 文章列表支持分类与标签组合筛选
验收：
- [ ] /posts?category=1&tag=2 返回同时满足的结果
- [ ] 分页链接保留筛选参数
- [ ] 无结果时展示空状态
- [ ] 补充 1 个测试
负责人：B
分支：feature/post-filter
```

### 5.3 看板列

`Backlog → Todo → In Progress → In Review → Done`

WIP 限制：每人同时最多 2 个 In Progress。

## 6. 代码评审分工

| PR 类型 | 第一评审 | 第二评审 |
| --- | --- | --- |
| 认证/权限/部署 | B | D |
| 文章/分类/搜索 | A | D |
| 前端/样式/模板 | E | A |
| 评论/收藏/账号 | A | B |
| 编辑器/上传/看板 | C | A |
| 数据库/模型 | A | D |
| 文档/PPT | 全员 | A |

评审要求：

- 至少 1 人 Approve；
- CI 通过；
- UI 变更附截图；
- 数据库变更说明迁移影响；
- 不 Reviewed-by 自己。

## 8. 沟通与文件规范

### 8.1 沟通渠道

| 渠道 | 用途 | 约定 |
| --- | --- | --- |
| 群聊 | 日常同步、快速提问 | 不贴大段代码，改用链接/文件 |
| GitHub Issue | 任务、bug、需求变更 | 一个 Issue 一个主题 |
| PR 评论 | 代码讨论 | 对事不对人，标注 must/nit/q |
| 周会 | 计划、风险、决策 | 有纪要，结论进 Issue |
| 共享文档 | 需求/接口/数据库 | 只保留一个最新版本 |

### 8.2 文件命名

```text
docs/01-项目需求文档.md
docs/02-数据库设计文档.md
deliverables/我的知识小栈-小组路演.pptx
deliverables/我的知识小栈-课程个人总结模板.docx
第三组作品-我的知识小栈系统的展示.mp4
```

### 8.3 版本与备份

- 代码：GitHub `main` + tag `v1.0.0`；
- 数据库：`mysqldump` 备份；
- 上传图片：打包 `uploads`；
- 文档：仓库 + 云盘各一份；
- 录屏：本地 + 云盘各一份；
- 答辩当天：U 盘 + 本地 + 云盘三份。

## 9. 风险与补位

| 风险 | 触发信号 | 补位方案 |
| --- | --- | --- |
| 某成员进度落后 | 连续 2 天无提交/站会缺席 | 组长拆分任务，B/C 补位 |
| 前端视觉反复 | 评审超过 3 轮 | 冻结设计 token，只修 bug |
| 数据库字段频繁变 | 联调后仍改表 | 冻结 schema，变更走 Issue |
| 演示环境故障 | 启动失败/网络异常 | 切换 Docker/备用库，播放录屏 |
| 答辩超时 | 彩排 > 9 分钟 | 压缩扩展页，保留主体演示 |

## 10. 提交前总检查

- [ ] `pytest -q` 全绿；
- [ ] Docker 或本机启动成功；
- [ ] 演示账号可登录；
- [ ] 演示数据完整（文章/评论/附件/看板）；
- [ ] README 步骤可复现；
- [ ] 文档无 `TODO`、无虚构链接；
- [ ] PPT 16 页、备注完整；
- [ ] 录屏命名正确、可播放；
- [ ] 个人总结无占位符残留；
- [ ] 仓库无 `.env`、数据库文件、上传图片；
- [ ] tag `v1.0.0` 已打，压缩包已备份。

---

> 分工的目的不是“把责任切开”，而是让每个人都知道下一步做什么、做完交给谁、怎样算完成。
