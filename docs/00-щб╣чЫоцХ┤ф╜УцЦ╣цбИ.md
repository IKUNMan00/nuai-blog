# 《我的知识小栈》项目整体方案

> 一页看清：为什么做、做什么、怎么做、谁来做、如何验收。

---

## 1. 项目定位

| 项 | 内容 |
| --- | --- |
| 项目名称 | 我的知识小栈——个人博客 / 笔记管理系统 |
| 项目性质 | 高校软件课程综合训练项目（小组，4 周） |
| 核心问题 | 学习笔记分散、只收藏不加工、项目经验无法复用 |
| 产品形态 | 单博主内容管理 + 读者互动 + 游客浏览的完整 Web 系统 |
| 技术路线 | Flask 3 + MySQL 8.0 + 原生 HTML/CSS/JavaScript |
| 交付形态 | 可运行代码 + 数据库脚本 + 文档 + PPT + 录屏脚本 + 个人总结模板 |

**一句话介绍**：把零散的知识，收进一座会生长的小栈。

---

## 2. 建设目标

1. **功能闭环**：登录 → 发文 → 分类打标 → 发布 → 浏览/搜索 → 评论审核 → 收藏 → 看板复盘；
2. **扩展加分**：Markdown 编辑器、收藏、评论审核、双主题、图片附件、数据看板；
3. **工程质量**：分层架构、ORM、CSRF、XSS 过滤、上传校验、13 个自动化测试；
4. **可部署**：Docker Compose 一条命令启动 MySQL + 应用；
5. **可答辩**：完整文档、16 页 PPT、6–8 分钟录屏脚本、20 个答辩问答。

---

## 3. 功能范围（摘要）

### 3.1 主体功能

- 用户登录 / 注册（博主 + 读者）
- 文章发布 / 编辑 / 删除 / 草稿
- 分类管理 / 标签管理
- 文章浏览 / 分页 / 详情
- 标题、摘要、正文搜索

### 3.2 扩展功能

- Markdown 编辑器（实时预览、图片插入）
- 文章收藏 / 我的收藏
- 访客与读者评论 / 后台审核
- 浅色 / 暗黑主题
- 图片附件管理
- 数据看板（文章数、访问、评论、分类分布、热门）

### 3.3 明确不做

多租户、多级评论、邮件通知、OAuth、全文搜索引擎、对象存储、移动 App。

---

## 4. 技术方案

```text
浏览器（Jinja2 页面 + 原生 JS）
        ↓
Flask 应用（main / auth / account / admin / api）
        ↓
SQLAlchemy ORM（预加载 / 事务 / 参数化）
        ↓
MySQL 8.0（9 张表）+ static/uploads（图片）
```

| 选择 | 理由 |
| --- | --- |
| Flask | 轻量、路由直观、适合课程讲解与快速部署 |
| MySQL 8.0 | 课程要求，支持事务、外键、索引、utf8mb4 |
| SQLAlchemy | 防注入、关系清晰、测试可切 SQLite |
| 原生前端 | 无框架依赖、离线可运行、降低讲解成本 |
| Docker Compose | 降低课堂部署成本，一条命令启动 |

## 8. 质量与风险

### 8.1 质量门禁

- `pytest -q` 全部通过；
- 读者访问后台返回 403；
- Markdown XSS 测试通过；
- 删除文章后评论/收藏不残留；
- 手机宽度无横向溢出；
- 浅色/暗黑均可读；
- Docker 一条命令启动。

### 8.2 主要风险

| 风险 | 应对 |
| --- | --- |
| MySQL 环境差异 | Docker Compose、UTF-8 配置、.env.example |
| 并行开发冲突 | 分支模型、模块拆分、PR 小步提交 |
| XSS / 越权 | 服务端过滤、统一权限校验、测试 |
| 进度延期 | P0 先闭环，扩展按周迭代，P2 可裁剪 |
| 演示环境故障 | 录屏备份、演示数据脚本、SQLite 测试兜底 |

## 9. 验收与路演

### 9.1 验收清单

- [ ] 博主登录、读者注册、游客浏览；
- [ ] 文章 CRUD、草稿/发布、分类/标签；
- [ ] 搜索、分页、详情、评论审核、收藏；
- [ ] Markdown 编辑器、图片上传、双主题、看板；
- [ ] 测试通过、Docker 可启动、文档齐全。

### 9.2 路演结构（8 分钟）

```text
问题 → 角色 → 需求 → 架构 → 数据库 → 视觉
→ 主体演示 → 扩展演示 → 技术难点 → 测试 → 协作 → 反思
```

配套 16 页 PPT 与 6–8 分钟录屏脚本。

---

## 10. 成功标准

1. 陌生人按 README 15 分钟内跑起来；
2. 教师能完整走通“发文 → 浏览 → 评论 → 审核 → 看板”；
3. 代码可解释、可测试、可回滚；
4. 路演 8 分钟内讲清“做了什么、为什么、怎么验证”；
5. 项目结束后仍愿意继续使用和维护。
