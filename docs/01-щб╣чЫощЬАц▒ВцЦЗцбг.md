## 1. 项目背景与目标

### 1.1 背景

软件工程专业学生在课程学习中会持续产生大量碎片化内容：课堂笔记、代码片段、报错记录、项目复盘、阅读摘录。它们通常散落在聊天记录、收藏夹、本地文档和多个云笔记工具里，存在三个问题：

1. **找不到**：缺少统一入口和有效检索，曾经解决的问题需要重新踩坑；
2. **留不住**：只收藏不加工，资料越存越多，真正能复用的经验很少；
3. **讲不清**：项目做完没有形成结构化复盘，无法在答辩、简历或面试中清楚表达。

因此，本项目设计并实现一个面向个人使用的博客 / 笔记管理系统。它既是一个可部署的完整 Web 软件，也是一次覆盖“需求—设计—开发—测试—部署—协作”的软件工程全流程训练。

### 1.2 项目目标

| 目标 | 可验证结果 |
| --- | --- |
| 做一套能真正使用的知识管理工具 | 博主可以注册登录、写 Markdown 笔记、分类打标签、发布与检索 |
| 覆盖课程要求的主体功能 | 登录注册、文章 CRUD、分类标签、浏览分页、搜索全部可用 |
| 完成至少 6 项扩展功能 | Markdown、收藏、评论审核、双主题、图片附件、数据看板 |
| 形成规范的软件工程资料 | 需求、数据库、概要设计、前端规划、接口、测试、部署、协作文档齐全 |
| 可课堂演示、可独立部署 | Docker Compose 一条命令启动；提供 6–8 分钟录屏脚本与路演 PPT |
| 体现小组协作 | GitHub 分支模型、提交规范、Issue/PR 模板、评审清单、分工表 |

### 1.3 成功标准

- 陌生同学按照 README 能在 15 分钟内跑起系统；
- 教师可以从前台浏览、搜索、评论，从后台完成发文、审核、看板查看的完整闭环；
- 核心页面在 1366×768 与手机宽度下均可用，浅色/暗黑主题均无阅读障碍；
- 自动化测试全部通过，无高危安全问题（SQL 注入、存储型 XSS、越权访问）；
- 答辩时能在 8 分钟内讲清“做了什么、为什么这样做、怎么验证”。

## 2. 项目范围

### 2.1 范围内（In Scope）

- 单博主个人博客的公开前台；
- 博主后台内容管理；
- 注册读者的收藏与评论；
- 游客浏览与游客评论；
- MySQL 数据库设计与部署脚本；
- 本地图片上传与附件管理；
- 访问统计看板；
- 响应式界面与双主题；
- 项目文档、测试、Docker 部署、GitHub 协作配置。

### 2.2 范围外（Out of Scope）

以下内容不作为本学期必做范围，在文档中作为“后续可扩展”说明：

- 多租户 / 多博主独立站点；
- 评论多级回复、点赞、@提醒；
- 邮件找回密码、短信验证、第三方 OAuth；
- 文章协同编辑、版本历史、定时发布；
- 全文搜索引擎（Elasticsearch / Meilisearch）；
- 对象存储、CDN、Redis 缓存；
- 移动端原生 App / 小程序。

明确边界可以避免“功能无限扩张、核心做不完”，符合课程项目的时间约束。

## 3. 用户角色与画像

### 3.1 角色定义

| 角色 | 说明 | 账号来源 | 典型行为 |
| --- | --- | --- | --- |
| 访客 Visitor | 未登录的普通浏览者 | 无需账号 | 浏览首页、搜索、读文章、提交游客评论 |
| 注册读者 Reader | 对内容有互动需求的读者 | 前台自主注册 | 收藏文章、以账号身份评论、管理个人资料、查看评论审核状态 |
| 博主 Admin | 站点所有者 / 唯一内容管理者 | 初始化脚本创建，或由管理员提升 | 写文章、管理分类标签、审核评论、管理附件、查看看板 |

### 3.2 用户画像

**画像 A：博主“阿栈”**
- 软件工程大三学生，正在准备课程项目与实习；
- 每周会写 1–2 篇技术笔记，希望有固定格式和统一归档；
- 关注页面是否“像自己的东西”，不喜欢千篇一律的后台模板；
- 需要知道哪些文章被读得多，哪些评论还没处理。

**画像 B：读者“小满”**
- 同专业学弟/学妹，通过课程群里的链接进入；
- 主要用手机浏览，偶尔收藏对自己有用的文章；
- 遇到问题时想留言，但不希望注册流程太复杂；
- 在意阅读体验：字距、代码块、暗色模式。

**画像 C：访客“林间”**
- 从搜索引擎或朋友分享进入，只看一篇文章；
- 不愿意注册，但愿意留下一条补充或感谢；
- 如果页面加载慢、排版拥挤，会立即离开。

## 4. 典型业务场景

### 场景 1：博主发布一篇项目复盘

1. 博主打开 `/auth/login`，使用 `admin` 账号登录；
2. 进入后台，点击“写新文章”；
3. 输入标题、摘要，选择“后端之道”分类，勾选 `Flask`、`MySQL` 标签；
4. 在 Markdown 编辑器中写正文，插入代码块与图片；
5. 右侧实时预览确认排版；
6. 点击“发布文章”，系统渲染安全 HTML、写入 `published_at`；
7. 前台首页与文章列表立即出现该文章，博主可在详情页预览。

**异常分支**：正文少于 10 字、标题为空、标签不存在、图片超过 5MB 时，系统保留已填内容并给出明确提示。

### 场景 2：访客留言并被审核

1. 访客从分享链接进入文章详情；
2. 阅读后在评论区填写昵称、可选邮箱和内容；
3. 提交后进入 `pending`，前台提示“审核通过后展示”；
4. 博主在后台“评论审核”看到待处理数量；
5. 博主点击“通过”，系统记录审核时间与审核人；
6. 访客刷新文章页，评论出现在公开列表。

**异常分支**：内容过短、昵称缺失、邮箱格式错误、20 秒内重复提交、蜜罐字段被填写，均不会写入公开评论。

### 场景 3：读者收藏并在手机端阅读

1. 读者注册账号（自动成为 `reader`）；
2. 在文章详情点击“收藏文章”，按钮变为“已收藏”；
3. 在“我的收藏”中分页查看；
4. 手机端打开同一页面，导航折叠、正文单列、代码块横向滚动；
5. 切换暗黑主题，页面颜色平滑变化，刷新后仍保持。

### 场景 4：博主通过看板判断内容效果

1. 博主进入 `/admin/dashboard`；
2. 查看总文章数、累计阅读、今日/7 日访问、待审核评论、收藏数；
3. 查看 7 日柱状趋势与分类占比；
4. 根据“热门文章”决定下一篇写什么；
5. 根据“最新动态”进入评论审核或文章编辑。

## 6. 非功能需求

### 6.1 性能

| 指标 | 要求 | 实现策略 |
| --- | --- | --- |
| 首屏响应 | 本机 < 500ms（不含图片） | 列表分页、关联预加载、SVG 封面 |
| 列表查询 | 不出现 N+1 | `joinedload` 分类/作者，`selectinload` 标签 |
| 图片 | 单张 ≤ 5MB，请求 ≤ 8MB | Pillow 校验 + 服务端限制 |
| 搜索 | 万级以内可用 | `LIKE` + 状态过滤；文档说明升级路径 |
| 前端资源 | 无外部 CDN 依赖 | 本地 CSS/JS/SVG，离线可运行 |

### 6.2 安全

- 密码使用 Werkzeug `generate_password_hash`，不可逆；
- 所有写请求启用 CSRF；
- ORM 参数化，禁止拼接 SQL；
- Markdown 经 bleach 白名单过滤，评论纯文本输出；
- 上传校验真实图片格式、尺寸、大小，UUID 存储名；
- 后台统一角色校验，防止水平/垂直越权；
- 跳转参数白名单校验，防止开放重定向；
- 敏感配置只放 `.env`，不提交仓库；
- 安全响应头：`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 等。

### 6.3 可用性

- 主要操作有明确成功/失败反馈；
- 表单错误保留用户输入；
- 删除操作二次确认；
- 空状态提供下一步行动；
- 键盘可访问：跳转主内容、可见焦点、`dialog` 焦点管理、`/` 打开搜索、Esc 关闭；
- 对比度满足 WCAG AA 的基本要求；
- 支持 `prefers-reduced-motion` 降级。

### 6.4 兼容性

- Chrome / Edge / Firefox 最近两个大版本；
- 桌面 1366×768 及以上；平板 768px；手机 375px；
- MySQL 8.0；Python 3.11–3.12；
- Docker Compose v2。

### 6.5 可维护性

- 应用工厂 + 蓝图按业务拆分；
- 配置与代码分离；
- 统一 CSS 设计变量，组件复用；
- 关键函数中文注释；
- 数据库字段、表、索引均有注释；
- 文档与代码一致，命令可复制执行。

### 6.6 可部署性

- 支持 Docker Compose 一键启动；
- 支持本机 MySQL + Gunicorn；
- 数据库初始化、演示数据生成均可重复执行；
- 上传目录可挂载卷持久化；
- 提供 `.env.example` 与健康检查。

## 7. 数据需求（概要）

系统需要持久化以下实体：

1. **用户**：登录凭证、昵称、角色、状态、最后登录时间；
2. **分类**：名称、说明、颜色、排序；
3. **标签**：名称、颜色；
4. **文章**：Markdown 原文、安全 HTML、摘要、封面、状态、置顶、浏览量、发布时间；
5. **文章-标签关系**：多对多；
6. **评论**：文章、用户/游客、内容、审核状态、审核人、审核时间；
7. **收藏**：用户与文章联合唯一；
8. **附件**：原始名、存储名、路径、MIME、大小；
9. **浏览明细**：文章、访客哈希、浏览时间，用于趋势统计。

详细字段、类型、索引、外键见《02 数据库设计文档》与 `database/schema.sql`。

## 8. 约束与假设

### 8.1 约束

- 课程周期约 4 周，小组 4–5 人，需并行开发；
- 必须使用 MySQL 8.0，不得只用内存数据库交差；
- 前端不使用 Vue/React 等复杂框架；
- 必须提供 GitHub 协作记录与提交规范；
- 必须能在课堂环境演示，不能依赖外网 CDN；
- 服务器可能没有公网域名，演示以本机/局域网为主。

### 8.2 假设

- 博主账号由项目组掌握，不开放后台注册；
- 文章以中文为主，数据库统一 `utf8mb4`；
- 单篇正文不超过 20 万字符，图片不超过 5MB；
- 演示数据由 `flask seed-demo` 生成，可重复初始化；
- 浏览器支持 ES6、CSS 变量、`<dialog>`。

## 10. 项目里程碑

## 11. 验收清单

### 11.1 功能验收

- [ ] 博主可登录，读者可注册，错误密码有提示；
- [ ] 博主可新建、编辑、发布、转草稿、删除文章；
- [ ] 分类和标签可增删改，文章可多选标签；
- [ ] 首页、列表、详情、分页、搜索均正常；
- [ ] 搜索可命中标题与正文，支持分类/标签组合；
- [ ] Markdown 标题、列表、代码块、表格、图片正确渲染；
- [ ] 读者可收藏/取消，收藏列表分页；
- [ ] 游客和读者可评论，默认待审核；
- [ ] 博主可通过/驳回/删除评论，前台只显示已通过；
- [ ] 图片上传成功，非图片和超大文件被拒绝；
- [ ] 看板数据与数据库一致；
- [ ] 浅色/暗黑主题切换正常，刷新保持；
- [ ] 手机宽度下导航、文章、后台表格可用。

### 11.2 非功能验收

- [ ] `pytest -q` 全部通过；
- [ ] Docker Compose 一条命令启动；
- [ ] 无明文密码、无 `.env` 入库；
- [ ] Markdown XSS 测试通过；
- [ ] 读者访问 `/admin` 返回 403；
- [ ] 删除文章后关联评论/收藏不残留；
- [ ] README 步骤可被陌生人复现。

### 11.3 答辩演示清单

1. 首页视觉与双主题；
2. 搜索 + 分类筛选；
3. 文章详情、代码块、目录、收藏；
4. 游客评论 → 后台审核 → 前台展示；
5. 后台看板数据；
6. Markdown 编辑与实时预览；
7. 图片上传与附件库；
8. 手机端响应式；
9. 数据库表结构与 GitHub 提交记录。
