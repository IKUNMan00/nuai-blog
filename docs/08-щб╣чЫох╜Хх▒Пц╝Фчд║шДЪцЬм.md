# 《我的知识小栈》项目录屏演示脚本

> 用途：课堂展示视频 / 提交材料
>
> 建议成片：6–8 分钟，1920×1080，30fps，MP4（H.264）
>
> **视频命名：`XX组作品-我的知识小栈系统的展示.mp4`**
>
> 例如：`第三组作品-我的知识小栈系统的展示.mp4`

---

## 1. 录制前准备

### 1.1 环境检查（提前 30 分钟）

- [ ] 演示数据库已重置：`flask seed-demo --reset`；
- [ ] 演示账号可登录：`admin / Admin@123`、`reader / Reader@123`；
- [ ] 首页、文章、后台均正常打开；
- [ ] 待审核评论 ≥2 条，已通过评论 ≥2 条；
- [ ] 图片附件 ≥3 张（或现场上传一张）；
- [ ] 浏览器缩放 100%，分辨率 1920×1080；
- [ ] 关闭微信、QQ、系统通知、无关标签页；
- [ ] 书签栏隐藏，浏览器窗口全屏（F11）；
- [ ] 录制软件：OBS Studio / Windows Xbox Game Bar / 剪映录屏；
- [ ] 麦克风测试，环境安静，语速略慢；
- [ ] 鼠标光标可见，必要时开启点击高亮；
- [ ] 准备一份备用录屏，防止现场网络/数据库异常。

### 1.2 推荐演示顺序

```text
首页 → 搜索 → 详情 → 游客评论 → 登录后台 → 看板 → 审核评论
→ 写文章（Markdown/图片）→ 发布 → 前台验证 → 收藏 → 主题/手机 → 结尾
```

### 1.3 录制参数

| 项 | 建议 |
| --- | --- |
| 分辨率 | 1920×1080 |
| 帧率 | 30fps |
| 编码 | H.264 / MP4 |
| 音频 | 48kHz，单声道/立体声 |
| 码率 | 6000–8000 kbps |
| 浏览器 | Chrome / Edge，100% 缩放 |
| 系统缩放 | 100%（避免字虚） |
| 鼠标 | 显示，移动慢，点击前停顿 0.5 秒 |

## 2. 分镜脚本（总时长约 7 分 30 秒）

### 镜头 1 · 片头（0:00–0:12）

**画面**

- 黑底/米白底标题卡：
  - 主标题：我的知识小栈
  - 副标题：个人博客 / 笔记管理系统
  - 小字：XX 组 · 课程综合训练项目 · 2026

**旁白**

> 大家好，我们是第 X 组。这是我们的小组作品——我的知识小栈，一个个人博客与笔记管理系统。

**操作**

- 无，后期加标题卡；
- 背景音乐淡入（音量 -22dB）。

---

### 镜头 2 · 首页第一印象（0:12–0:40）

**画面**

- 打开 `http://127.0.0.1:5000/`；
- 鼠标从 Hero 缓慢下移，展示数据带、最新文章、分类、热门、标签；
- 在分类卡和文章卡上各悬停一次，展示动效。

**旁白**

> 首页是整座小栈的入口。左边是站点主张和最新数据，右边用层叠便签呈现置顶笔记。往下是最新文章、分类、热门文章、标签云。整个页面没有使用前端框架，视觉和交互都是原生 HTML、CSS 和 JavaScript 完成的。

**操作要点**

- 滚动速度慢，不要快速甩动；
- 在每个区块停留 2–3 秒；
- 不要点击登录/注册。

---

### 镜头 3 · 搜索与筛选（0:40–1:05）

**画面**

- 点击右上角搜索图标（或按 `/`）；
- 输入 `Flask`，点击搜索；
- 展示结果数、分类 chips；
- 点击“后端之道”分类，展示组合筛选；
- 再点击“清除全部”。

**旁白**

> 搜索支持标题、摘要和正文的关键词匹配，并且可以和分类、标签组合。比如搜索 Flask，再筛选后端分类，结果会同时保留两个条件。当前用 LIKE 实现，数据量上来后会升级到 MySQL 全文索引。

**操作要点**

- 输入时让观众看清关键词；
- 结果页停留 3 秒；
- 不要打开空结果页。

---

### 镜头 4 · 文章详情（1:05–1:35）

**画面**

- 点击《从零搭建一座会生长的知识栈》；
- 展示标题、作者、阅读量、封面、正文；
- 滚动到代码块、引用、表格；
- 右侧目录随滚动高亮（如未实现高亮，展示目录锚点）；
- 点击“收藏文章”（先登录 reader）或展示收藏数；
- 滚动到评论区。

**旁白**

> 详情页支持 Markdown 正文、代码块、表格、引用和图片。右侧目录根据正文标题自动生成。文章底部可以收藏、复制链接，博主还能直接进入编辑。再往下是读者留言。

**操作要点**

- 在代码块停留 2 秒；
- 鼠标划过目录，不点太多；
- 收藏按钮状态变化给特写。

---

### 镜头 5 · 游客评论与审核（1:35–2:15）

**画面**

- 在评论表单填写：昵称“演示访客”，内容“这是一条课堂演示评论，用来展示审核流程。”；
- 提交；
- 展示“审核通过后展示”的提示；
- 刷新页面，评论仍不显示（说明待审核）；
- 切换到后台，登录 admin；
- 打开“评论审核”，找到刚提交的评论；
- 点击“通过”；
- 切回前台刷新，评论出现。

**旁白**

> 评论默认不会直接公开，而是进入待审核队列。访客提交后，前台只提示“审核通过后展示”。博主在后台看到待处理数量，点击通过，评论才会出现在文章页。这样既保留开放讨论，又避免垃圾评论。

**操作要点**

- 提前开好两个窗口，左右分屏或 Alt+Tab；
- 提交后不要立刻刷新，先让提示停留；
- 审核通过后前台刷新要完整展示评论。

---

### 镜头 6 · 后台看板（2:15–2:45）

**画面**

- 后台 `/admin/dashboard`；
- 鼠标依次经过四张指标卡；
- 展示 7 日柱状图、分类环形图；
- 展示热门文章、最新动态；
- 点击“写新文章”。

**旁白**

> 后台看板汇总文章数、阅读量、今日和近七日访问、待审核评论、收藏次数，以及分类分布和热门文章。浏览明细按会话去重，博主预览不计入。它不是静态数字，而是和数据库实时联动。

**操作要点**

- 不要逐字念所有数字；
- 强调“7 日趋势”和“待审核”；
- 进入写文章。

---

### 镜头 7 · Markdown 编辑器（2:45–3:45）

**画面**

- 在标题输入：`课堂演示：如何用 3 步整理一条笔记`；
- 摘要输入：`一条课堂演示文章，用来展示 Markdown 编辑器。`；
- 选择分类“学习方法”，勾选 `Markdown`、`效率`；
- 在正文输入：

```markdown
## 为什么要整理笔记？

因为**能复用的知识**才有价值。

### 三个步骤

1. 记录场景
2. 写下结论
3. 补充反例

> 一条好笔记，应该能回答一个真实问题。

```python
def organize(note):
    return note.strip()
```
```

- 展示右侧实时预览；
- 点击工具栏“加粗”“代码块”各一次；
- 点击图片按钮，上传一张本地图片；
- 展示图片插入 Markdown 与预览。

**旁白**

> 编辑器左边写 Markdown，右边实时预览。工具栏支持标题、列表、引用、代码块、链接、表格，也支持快捷键。预览不是前端随便渲染，而是调用后端统一渲染并过滤，所以和最终详情一致。图片可以点按钮、粘贴或拖拽上传，自动插入 Markdown。

**操作要点**

- 输入速度适中，不要全部现场敲长文；
- 可提前准备文本，用剪贴板粘贴；
- 上传图片提前准备一张 <1MB 的 PNG；
- 展示“图片已上传并插入正文”的提示。

---

### 镜头 8 · 发布与前台验证（3:45–4:15）

**画面**

- 点击“发布文章”；
- 回到文章列表，展示新文章；
- 点击进入详情，展示标题、正文、代码块、图片；
- 回到列表，演示编辑 → 转草稿 → 前台不可见（可选）；
- 删除演示文章（可选，保留数据则跳过）。

**旁白**

> 点击发布后，文章立即出现在前台。标题、摘要、分类、标签、封面和正文都已保存。草稿只对博主可见，访客访问会得到 404。删除会同时清理评论、收藏和浏览记录。

**操作要点**

- 新文章标题带“课堂演示”，容易找到；
- 发布后刷新一次列表；
- 如果时间不够，跳过删除，保留文章给观众看。

---

### 镜头 9 · 收藏与账号中心（4:15–4:40）

**画面**

- 退出 admin，登录 `reader / Reader@123`；
- 打开一篇文章，点击“收藏文章”；
- 进入右上角头像 → 我的收藏；
- 展示收藏卡片；
- 进入“我的评论”，展示审核状态。

**旁白**

> 读者账号可以收藏文章、参与评论。收藏用联合主键防止重复，收藏列表和评论记录都在账号中心。普通注册用户是读者角色，不能进入后台，这样权限边界更清晰。

**操作要点**

- 提前退出 admin，避免角色混淆；
- 收藏按钮文案从“收藏文章”变“已收藏”；
- 账号中心展示昵称、角色、统计。

---

### 镜头 10 · 图片附件与双主题（4:40–5:05）

**画面**

- 用 admin 登录，进入“图片附件”；
- 展示附件网格；
- 点击“MD”复制 Markdown（展示提示）；
- 返回前台，点击右上角主题按钮；
- 切换暗黑，滚动首页和文章；
- 刷新页面，主题保持。

**旁白**

> 图片附件统一管理，支持复制 Markdown 和 URL。主题切换只改一组 CSS 变量，所有页面同步生效，并且记住用户选择。暗黑模式不是简单反色，文字对比、卡片边框、代码块都单独调整过。

**操作要点**

- 暗黑模式停留 5 秒，展示文章正文；
- 刷新后确认仍为暗黑；
- 再切回浅色，方便后续录制。

---

### 镜头 11 · 手机端 / 响应式（5:05–5:25）

**画面**

- 打开浏览器开发者工具（F12）→ 设备模拟（iPhone 12 / 390×844）；
- 刷新首页，展示折叠导航；
- 打开导航，点击“文章”；
- 打开一篇文章，展示单列正文、代码块横向滚动；
- 展示评论区表单。

**旁白**

> 手机端重新排布了导航、Hero、文章网格和详情侧栏。表格和代码块可以横向滚动，按钮和表单适合触控。后台也做了移动端导航，不是只在电脑上能用。

**操作要点**

- 不要展示开发者工具面板本身，只展示页面；
- 若设备模拟不方便，提前录好手机真机视频插入。

**画面**

- 回到首页 Hero；
- 叠加结束卡：

  - Flask + MySQL 8.0 + 原生前端
  - 主体 5 项 + 扩展 6 项

## 4. 录制执行清单

### 4.1 录制前

- [ ] 关闭通知：Windows 专注助手 / 勿扰模式；
- [ ] 关闭无关浏览器标签；
- [ ] 浏览器缩放 100%，全屏；
- [ ] 清理桌面，隐藏任务栏（可选）；
- [ ] 准备演示文本与图片；
- [ ] 录屏软件试录 10 秒，检查声音与画面；
- [ ] 手机静音，门口挂牌。

### 4.2 录制中

- 每段停顿 1 秒再开始说话，方便剪辑；
- 操作前先停顿，点击后再讲；
- 说错不要停，重录该段即可；
- 不要移动窗口或切换分辨率；
- 保持鼠标在画面内，移动慢。

### 4.3 录制后

- 检查画面是否清晰、声音是否同步；
- 剪掉登录等待、上传等待、错误重试；
- 加片头/片尾、字幕（可选）；
- 音量标准化到 -16 LUFS 左右；
- 导出 1080p MP4；
- 按规范命名：

```text
XX组作品-我的知识小栈系统的展示.mp4
```

- 本地 + 云盘各备份一份；
- 提交前用播放器完整看一遍。

## 5. 常见问题与处理

| 问题 | 处理 |
| --- | --- |
| 录制时数据库为空 | 提前 `flask seed-demo --reset`，不要现场初始化 |
| 搜索无结果 | 用首页分类进入，不要连续试错；剪辑掉失败段 |
| 图片上传失败 | 提前准备小图；失败时展示附件库已有图片 |
| 评论提交太快被限频 | 等 20 秒，或换一个浏览器会话；剪辑掉 |
| 登录过期 | 提前重新登录；录制中不要清 Cookie |
| 通知弹出 | 开启勿扰模式，重新录制该段 |
| 声音有回声 | 用耳机麦克风，关闭外放 |
| 视频太大 | 1080p / 30fps / H.264，码率 6–8Mbps |
| 时间超 8 分钟 | 优先删减 9–11 页的细节，保留主体演示 |

## 6. 视频结构模板（剪辑时间线）

```text
00:00  片头标题（12s）
00:12  首页（28s）
00:40  搜索筛选（25s）
01:05  文章详情（30s）
01:35  游客评论 → 后台审核（40s）
02:15  数据看板（30s）
02:45  Markdown 编辑器（60s）
03:45  发布与前台验证（30s）
04:15  收藏与账号中心（25s）
04:40  附件与双主题（25s）
05:05  手机端（20s）
05:25  结尾（25s）
05:50  片尾 / 谢谢（5s）
```

> 如果讲解较慢，可延长到 7–8 分钟；不要超过 10 分钟，课堂时间有限。

## 7. 提交命名与格式

| 项 | 要求 |
| --- | --- |
| 文件名 | `XX组作品-我的知识小栈系统的展示.mp4` |
| 格式 | MP4（H.264） |
| 分辨率 | 1920×1080 |
| 帧率 | 30fps |
| 时长 | 6–8 分钟 |
| 大小 | 建议 < 500MB |
| 音频 | 清晰人声，无爆音 |
| 字幕 | 可选，建议加中文字幕 |
| 备份 | 本地 + 云盘 |

> 录屏的核心不是“展示所有功能”，而是让评委在几分钟内看到：系统能跑、流程完整、界面美观、讲解清楚。宁可少演示一个页面，也不要把时间花在等待和修错误上。
